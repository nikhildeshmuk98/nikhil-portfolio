Overview

Why Deepflix?

Choosing what to watch on OTT platforms takes longer than watching it. Deepflix removes that friction by understanding the story of a movie, not just its title, genre tag or popularity.

Purpose

Deepflix is a web application that recommends movies and OTT content by analysing the script / story text of each title. Using NLP, a CNN and sentiment analysis, it learns what a story is really about and matches it to what each user enjoys.

Instead of showing the same trending list to everyone, every user gets a personalised feed that improves with their ratings, preferences and viewing progress.

Who it helps

  • Movie lovers who are tired of endless scrolling and want relevant picks fast.
  • New users who want good suggestions right after setting their preferences.
  • Binge watchers who want to resume titles and track viewing progress.
  • Students & developers who want a practical example of NLP + deep learning in a real web app.

How it works

Story text from the database is cleaned and tokenised, passed through a 1D CNN that learns genre and theme patterns, and combined with sentiment signals and the user's behaviour. A hybrid recommendation engine then ranks content for each user.

The full journey is shown in the six steps below.

The Deepflix Workflow

User Preferences

The user signs up, picks preferred genres and starts browsing, rating and watching movies. These actions become personalisation signals.

Script Analysis (NLP)

The story/script of each title is cleaned, tokenised and converted into fixed-length numeric sequences that a neural network can read.

CNN Learning

A 1D Convolutional Neural Network scans the text for meaningful phrase patterns and learns to connect story content with genres and themes.

Sentiment Analysis

The emotional tone of a story (uplifting, dark, tense, romantic) is measured so recommendations can match the mood the user likes.

Hybrid Engine

Content-based scores from the story analysis are blended with user-based signals such as ratings and history to produce one ranked list.

Personal Feed

Top results are shown in the app, with movie browsing, ratings and viewing-progress tracking keeping the loop learning.

The Problem & The Solution

What we noticed while using OTT platforms, and how Deepflix answers each issue.

Problems We Saw

Decision fatigue

Thousands of titles across platforms make it hard to pick one. Users spend more time browsing than watching.

Shallow recommendations

Most suggestions rely on genre tags, popularity or what is trending, so they ignore the actual story and themes.

One-size-fits-all feeds

Generic lists do not reflect individual taste, mood or viewing history.

Cold start for new users

With no history, a new user gets poor suggestions until enough data is collected.

No story understanding

Two films with the same genre label can feel completely different. Metadata alone cannot capture that.

Problems We Solved

Faster choices

A short, ranked, personalised list replaces endless scrolling.

Story-aware recommendations

NLP and a CNN read the script text and learn genre and theme patterns directly from the story.

Personalisation

Ratings, preferences and viewing progress feed a hybrid engine so each user sees a different feed.

Better first experience

Content-based story analysis works even for new users, since it needs only the movie's text and not a long history.

Mood matching

Sentiment analysis adds the emotional tone of a story to the recommendation logic.

Honest Evaluation

Advantages & Limitations

Advantages

  • Story-based understanding using NLP and a CNN rather than only tags.
  • Hybrid design that can mix content-based and user-based signals.
  • Sentiment analysis adds emotional context to suggestions.
  • Full-stack web app with browsing, ratings, preferences and progress tracking.
  • Retrainable model: the Flask app can call the training script to learn from new content in the database.
  • Visual metrics such as accuracy and loss curves and a confusion matrix are saved after training.
  • Lightweight stack that is simple to deploy on Render.

Limitations

  • Hybrid engine is a placeholder: the current HybridEngine returns fixed IDs 1 to 10 and the real blending logic is the next milestone.
  • Small dataset: the CNN learns only from the stories stored in the database, so accuracy depends on how much and how clean that text is.
  • Genre labels are multi-label, but evaluation compares only the top predicted genre, which is a simplified view.
  • Text only: posters, trailers, cast and audio are not analysed.
  • English text: TextBlob and the tokenizer are tuned for English stories.
  • Older ML stack: TensorFlow 2.10 and pinned dependencies need careful version management.
  • Hosting cold starts: free-tier hosting may take a few seconds to wake up on the first visit.

train_model.py

How the CNN Model Is Trained

The Flask app calls this script to read stories from MySQL, train a 1D CNN to learn genres from text, and save the model and its helper files.

MySQL contents Clean & split genres Tokenize + pad Train CNN Save model Metrics & plots

1. Fetch the data

The script connects to MySQL with PyMySQL (DB_CONFIG) and runs SELECT id, story, genre FROM contents. If the connection fails or the table is empty, training stops safely with a message.

Rows are loaded into a pandas DataFrame, missing stories are replaced with empty text, and genre strings such as "Action, Drama" are split into clean lists. Rows with no genre are dropped.

2. Preprocess

MultiLabelBinarizer turns each genre list into a 0/1 vector, so one movie can belong to several genres.

The Tokenizer keeps the 10,000 most common words (VOCAB_SIZE) and maps unknown words to <unk>. Each story becomes a sequence of numbers, then pad_sequences makes every story exactly 500 tokens long (MAX_SEQUENCE_LENGTH).

3. Train / validation split

train_test_split keeps 80% of stories for training and 20% for validation, with random_state=42 so results are repeatable.

Validation data is never used to update the model. It shows whether the CNN generalises to stories it has not seen.

Model Architecture

LayerSettingsWhat it does
Embedding10000 words → 128 dimsConverts each word number into a dense 128-value vector that captures meaning.
Conv1D128 filters, kernel 5, ReLUSlides across the text and detects 5-word phrase patterns that signal a genre or theme.
GlobalMaxPooling1D-Keeps the strongest signal from each filter, producing one fixed-size summary of the whole story.
Dense64, ReLUCombines the detected patterns into higher-level features.
Dropout0.5Randomly switches off half of the neurons while training to reduce overfitting.
Dense embedding_layer32, ReLUA compact 32-value story representation. It is named so it can be read out as a feature vector for similarity.
Dense (output)one unit per genre, SoftmaxOutputs a probability for each genre.

The model is compiled with the Adam optimiser and categorical cross-entropy loss, tracking accuracy. It trains for 20 epochs with a batch size of 32.

What gets saved

pretrained_model.keras

The trained CNN, saved in data/ so the Flask app can load it instantly without retraining.

tokenizer.pkl & mlb.pkl

The fitted tokenizer and genre binarizer. They must be reused at prediction time so new text is encoded exactly like the training text.

Metrics & plots

train_model.py · core of the model
def create_classification_model(vocab_size, max_len, emb_dim, filters, kernel, drop, num_classes):
    model = Sequential([
        Embedding(input_dim=vocab_size, output_dim=emb_dim, input_length=max_len),
        Conv1D(filters=filters, kernel_size=kernel, activation='relu'),
        GlobalMaxPooling1D(),
        Dense(64, activation='relu'),
        Dropout(drop),
        Dense(32, activation='relu', name='embedding_layer'),
        Dense(num_classes, activation='softmax')
    ])
    model.compile(optimizer='adam', loss='categorical_crossentropy', metrics=['accuracy'])
    return model

Planned design

What a hybrid engine combines

A hybrid recommender mixes two families of signals so each covers the other's weakness:

  • Content-based: pass last_story through the CNN to get its 32-value embedding_layer vector, then find titles with the most similar vectors (for example by cosine similarity).
  • User-based: use ratings, preferences and viewing progress for user_id to boost titles liked by similar users.
  • Sentiment: nudge scores toward the mood the user usually enjoys.
